# M7 · G1 — Esercizio: gli agenti escono dal repo con MCP

**Pomeriggio, individuale, sul tuo repository.** Stesso esercizio per tutti.
Obiettivo: vedere il protocollo MCP "nudo", collegare due server MCP a Copilot in VS Code,
usarli insieme per verificare l'app e **decidere quali server ammettere**.

```
MCP Inspector ──► server everything        (fase 1: il protocollo senza modello)
VS Code + Copilot (Agent) ──► Playwright MCP ──► la tua app su localhost:8080
                          └─► GitHub MCP     ──► issue nel tuo repo
```

Il `main` del tuo repo è protetto dal ruleset del Modulo 6: lavora sul branch `m7-g1` e
porta tutto su `main` con una pull request a fine giornata.

Prerequisiti: Node.js **22.19 o più recente** (`node --version`), VS Code aggiornato,
la tua app che parte con `.\mvnw.cmd spring-boot:run`.

## 1 · Il protocollo nudo, con MCP Inspector (40 min)

```bash
npx @modelcontextprotocol/inspector npx -y @modelcontextprotocol/server-everything@2.1.0
```

Apri l'URL che compare nel terminale (contiene il token di sessione: non scrivere a mano
`localhost:6274`). Collegati con il transport **STDIO**, poi:

1. Guarda la risposta a `initialize`: versione del protocollo, `capabilities` del server,
   `serverInfo`.
2. **Tools** → elenca i tool. Apri `echo`: descrizione, `inputSchema`, `annotations`.
3. Chiama `echo` con `ciao`; chiama `get-sum` con `a` = `x` (una stringa al posto di un
   numero). Che differenza c'è tra le due risposte?
4. **Resources**: leggi una risorsa. **Prompts**: apri `args-prompt` e compilalo.
5. Nella vista dei messaggi JSON-RPC (Protocol / History) copia una richiesta `tools/call`
   e la sua risposta.

Compila `docs/mcp/protocollo.md` (modello in fondo).

## 2 · Due server MCP nel tuo VS Code (40 min)

1. Nel `.gitignore` sostituisci la riga `.vscode/` con queste due, così `mcp.json` si
   versiona e il resto della cartella no:

   ```
   .vscode/*
   !.vscode/mcp.json
   ```

2. Crea `.vscode/mcp.json`:

   ```json
   {
     "servers": {
       "github": {
         "type": "http",
         "url": "https://api.githubcopilot.com/mcp/",
         "headers": { "X-MCP-Toolsets": "repos,issues,pull_requests" }
       },
       "playwright": {
         "type": "stdio",
         "command": "npx",
         "args": ["-y", "@playwright/mcp@0.0.83", "--isolated"]
       }
     }
   }
   ```

3. **MCP: List Servers** → avvia i due server; per GitHub accetta il login OAuth (niente
   token nel file).
   `--isolated` tiene il profilo del browser in memoria: niente cookie salvati su disco.
   Se Chrome non c'è, aggiungi `"--browser", "msedge"`.
4. Apri la chat in modalità **Agent** → icona degli strumenti: quanti tool vedi per ogni
   server? Annotalo in `protocollo.md`.

## 3 · Playwright verifica l'app, GitHub scrive la issue (60 min)

1. Avvia l'app (`.\mvnw.cmd spring-boot:run`).
2. In Agent chiedi di verificare con Playwright il **riassortimento** (`/prodotti`, link
   «Riassortisci»), con questi casi: 1 e 1000 pezzi (validi), 0 e 1001, quantità vuota,
   quantità non numerica, nota di 250 e di 251 caratteri. Per ogni caso: cosa mostra la
   pagina e se la giacenza cambia (controlla `/movimenti`).
   Suggerimento: alcuni casi il browser li blocca da solo (`min`, `max`, `maxlength`);
   chiedi all'agente di provarli **anche** inviando il form senza quei controlli. Il
   server li rifiuta da solo?
3. **Approva una chiamata alla volta** e leggi cosa sta per fare ogni tool prima di
   approvare. Annota quali chiamate ti hanno chiesto conferma.
4. Chiedi all'agente di aprire con GitHub MCP una issue «Verifica esplorativa del
   riassortimento» nel tuo repo, con la tabella dei casi e i difetti trovati.
   Prima di approvare `create_issue` controlla titolo, testo e repository.

## 4 · Quali server ammetti (40 min)

1. Cambia l'URL di GitHub in `https://api.githubcopilot.com/mcp/readonly`, riavvia il
   server e riconta i tool: quali sono spariti?
2. Compila `docs/mcp/server-ammessi.md` per **github**, **playwright** e un terzo server a
   scelta trovato con `@mcp` nella vista Extensions di VS Code (senza installarlo).
3. Commit sul branch `m7-g1`, pull request, merge (con i controlli del Modulo 6).

## Fatto quando

- `docs/mcp/protocollo.md` contiene una coppia `tools/call` → risposta vera e la differenza
  tra un errore di protocollo e un risultato con `isError`;
- `.vscode/mcp.json` è nel repo, senza token, con la versione di Playwright fissata;
- nel repo c'è la issue «Verifica esplorativa del riassortimento» scritta con GitHub MCP;
- `docs/mcp/server-ammessi.md` ha la scheda di tre server con una decisione motivata.

# M7 · G2 — Esercizio: il magazzino diventa un MCP server

**Pomeriggio, individuale, sul tuo repository.** Stesso esercizio per tutti.
Obiettivo: aggiungere alla tua applicazione un **MCP server** scritto in Java con
**Spring AI**, con quattro tool progettati per un agente, provarlo con l'Inspector e con
un client MCP nei test, e usarlo da Copilot in VS Code.

```
Copilot (Agent) ──HTTP──► /mcp ──► mcp.MagazzinoTools ──► service ──► model, repository
MCP Inspector  ──HTTP──┘          (un ingresso come web)
```

Lavora sul branch `m7-g2` e chiudi con una pull request (il `main` è protetto).
Il package `mcp` segue le regole di `.github/instructions/architettura.instructions.md`:
chiama i `service`, mai i `repository`.

## 1 · La dipendenza e le proprietà (40 min)

Nel `pom.xml`, la versione di Spring AI tra le `properties`, il BOM e lo starter:

```xml
<spring-ai.version>2.0.2</spring-ai.version>
```

```xml
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-bom</artifactId>
      <version>${spring-ai.version}</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
```

```xml
<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-starter-mcp-server-webmvc</artifactId>
</dependency>
```

In `application.properties`:

```properties
spring.ai.mcp.server.name=magazzino
spring.ai.mcp.server.version=0.3.0
spring.ai.mcp.server.type=SYNC
spring.ai.mcp.server.protocol=STREAMABLE
spring.ai.mcp.server.streamable-http.mcp-endpoint=/mcp
```

Attenzione: `protocol=STREAMABLE` va scritto. Se manca, Spring AI 2.0 attiva il vecchio
trasporto SSE, deprecato.

Avvia l'app e collegati con l'Inspector (`npx @modelcontextprotocol/inspector`), transport
**Streamable HTTP**, URL `http://localhost:8080/mcp`: `serverInfo` dice `magazzino`, la
lista dei tool è vuota.

## 2 · Tre tool di lettura (60 min)

Le regole:

- **R1** `cerca_prodotti(testo)`: prodotti il cui codice o nome contiene il testo,
  maiuscole indifferenti. Meno di 2 caratteri (spazi esclusi) = errore «Scrivi almeno 2
  caratteri da cercare». Al massimo 20 prodotti, più `trovati` con il numero totale.
- **R2** `prodotti_sotto_scorta()`: prodotti con giacenza uguale o inferiore alla scorta
  minima, dal più scoperto (scorta minima − giacenza, decrescente); a parità, per codice.
- **R3** `dettaglio_ordine(numero)`: cliente, stato, righe con lo sconto, spese di
  spedizione e totale da pagare. Ordine inesistente = errore «Ordine N non trovato».
- **R6** nessun tool restituisce un'entità JPA: record propri nel package `mcp`
  (`ProdottoMcp`, `ElencoProdotti`, `OrdineMcp`). Una lista va dentro un oggetto.

Le ricerche (R1, R2) sono casi d'uso: vanno in `CatalogoService` (`cerca`, `daRiassortire`)
con i loro test. Nel package `mcp` una classe `@Component` con i metodi `@McpTool`:

```java
@McpTool(name = "prodotti_sotto_scorta", description = """
    Elenca i prodotti da riassortire: giacenza uguale o inferiore alla \
    scorta minima, dal più scoperto. Usalo per le domande sulle scorte e \
    prima di proporre un riordino.""", generateOutputSchema = true,
    annotations = @McpAnnotations(title = "Prodotti sotto scorta",
        readOnlyHint = true, destructiveHint = false, idempotentHint = true,
        openWorldHint = false))
public ElencoProdotti prodottiSottoScorta() {
  return ElencoProdotti.di(catalogo.daRiassortire(), MASSIMO_PRODOTTI);
}
```

Riavvia e prova i tre tool con l'Inspector, anche con gli errori.

## 3 · Il tool che scrive e i test con un client MCP (60 min)

- **R4** `riassortisci_prodotto(codice, quantita, nota?)`: le stesse regole della pagina
  (da 1 a 1000 pezzi, nota facoltativa fino a 250 caratteri), movimento CARICO; restituisce
  codice, nome, pezzi aggiunti, giacenza nuova e se è ancora da riassortire.
- **R5** annotazioni: i tre tool di lettura `readOnlyHint = true`, `idempotentHint = true`;
  quello che scrive `readOnlyHint = false`, `destructiveHint = false` (aggiunge, non
  cancella), `idempotentHint = false`. La descrizione dice che modifica i dati.
- **R7** gli errori del dominio (`MagazzinoException`) arrivano al modello come risultato
  con `isError` e il messaggio in italiano: non catturarli nel tool.

Un test `@SpringBootTest(webEnvironment = RANDOM_PORT)` con un client MCP vero:

```java
client = McpClient.sync(HttpClientStreamableHttpTransport
    .builder("http://localhost:" + porta).build()).build();
client.initialize();
CallToolResult risultato = client.callTool(CallToolRequest
    .builder("riassortisci_prodotto")
    .arguments(Map.of("codice", CODICE, "quantita", 1001)).build());
assertTrue(risultato.isError());
```

Almeno tre test: i quattro nomi con le annotazioni giuste; un errore leggibile
(ordine inesistente); un riassortimento fuori limite che **non** cambia la giacenza.
Usa un prodotto creato dal test, non quelli di `DatiIniziali`.

Prima del commit: `.\mvnw.cmd spotless:apply` (la CI controlla la formattazione), poi
`.\mvnw.cmd test`.

## 4 · Copilot usa il tuo server (30 min)

1. In `.vscode/mcp.json` aggiungi:

   ```json
   "magazzino": { "type": "http", "url": "http://localhost:8080/mcp" }
   ```

2. Con l'app avviata, **MCP: List Servers** → avvia `magazzino`. In Agent chiedi:
   «Quali prodotti sono sotto scorta?», «Quanti tasselli abbiamo?», «Cosa c'è nell'ordine 1?»
   (crea prima un ordine dalla pagina). Quali tool ha scelto? Con quali argomenti?
3. Chiedi «Riassortisci TAS-8 di 20 pezzi, nota DDT 123»: deve chiederti conferma.
   Controlla `/movimenti`.
4. Facoltativo: il prompt `piano-riordino` con `/magazzino.piano-riordino`.
5. Commit, PR, merge.

## Fatto quando

- `.\mvnw.cmd test` è verde, con i test del service e i test con il client MCP;
- l'Inspector mostra quattro tool, con le annotazioni di R5;
- Copilot ha risposto alle tre domande con i tuoi tool e ha chiesto conferma prima di
  riassortire;
- la PR è mergiata e il package `mcp` non importa nessun `repository`.
